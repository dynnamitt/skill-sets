# graph-in-pane Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Claude Code mod that shows Graphviz graphs of scripts, builds,
`.dot` files and plans as images in one docked pane. It has commands
`/graph-tree` (`/10kfv`), `/graph-flow` (`/10kfo`) and `/graph`, a
`show_graph` tool for Claude, and an automatic plan graph.

**Architecture:**
- One hooks module (`hooks/register.tsx`) wires events to small modules in
  `hooks/lib/`.
- External work goes through `$.process.run`: `ast-grep` extracts, `dot`
  renders, `tree-sitter` is the fallback, `nvim` discovers parsers.
- Pure functions turn ast-grep rows into a `Skeleton`, a `Skeleton` into
  DOT, and DOT into an alt outline. The breadcrumb is a pure reducer.
- Pane state lives in `$.state` atoms declared in `types/index.d.ts`.

**Tech Stack:**
- Claude Code 2.1.310 mod API (`import … from 'claude-code'`); tests use
  `claude-code/testing`.
- TypeScript/TSX.
- ast-grep 0.51 and Graphviz `dot` on the host.

**Spec:** `graph-in-pane/docs/2026-10-25-design.md`. Read it first. This
plan argues from it.

API reference for this build:
- Types:
  `/tmp/claude-1000/bundled-skills/2.1.310/08030fd2649bb44be3210dc6a31d128d/plugin-authoring/types/claude-code.d.ts`
  (grep it, don't read it whole). After the first load the same file is at

- Reference: `reference.md` and `examples/` in the same folder.

## Global Constraints

- **Location.** All plugin files live under
  `~/code/skill-sets/graph-in-pane/` (repo `dynnamitt/skill-sets`, public).
  Commit each task as its own commit, ending with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push.
- **Code style.** Functional: `map`/`filter`/`reduce`/`flatMap`, `const`,
  no mutation-heavy loops. Pure functions in `lib/` take plain data and
  return plain data.
- **Any Linux distro.** No hardcoded tool paths. Look up on `PATH`, then
  `/home/linuxbrew/.linuxbrew/bin`, `$HOME/.linuxbrew/bin`,
  `$HOME/.cargo/bin` and `$HOME/.local/bin`. `userConfig` fields override.
- **Executable names.** Always run `ast-grep`, never `sg`.
- **Files and privileges.** Temp and cache files go only under
  `${XDG_CACHE_HOME:-$HOME/.cache}/graph-in-pane/`. Nothing needs `sudo`.
- **Graphs.** Graphviz only: no Mermaid, no SVG. Top-down (`rankdir=TB`).
- **Keys.** Hotkeys are digits `1`–`9` (open), `0` (back) and `m` (more).
  Never bracket or symbol keys. The pane is never opened with
  `focus: true`.
- **Pane.** One pane id, `graph`.
- **Tool.** The tool is `show_graph`, registered with `isDeferred: false`.
  The model sees it as `mcp__graph-in-pane__show_graph`.
- **Drill-down.** Only into own files: inside the target's directory or git
  repo, never `node_modules`. No other code is followed.
- **Markdown.** Every `.md` file in the repo has `name`/`description`
  frontmatter.

## Review Focus

1. **Path forms.** A path argument may be relative, start with `~`, or
   contain spaces (`/graph-tree "my dir/run.sh"`). It resolves against the
   session cwd. Pinned in Task 6 (`resolveTarget`).
2. **Bad targets.** A missing file, an unsupported extension, a binary
   file, or an empty dir shows a one-line error in the pane, keeps the
   previous graph in the breadcrumb, and never throws. Pinned in Task 6.
3. **Huge directories.** A dir containing `node_modules`, `.git`, `dist`
   or thousands of files skips the ignored dirs and caps at 200 files, then
   shows a `+N more` node. Pinned in Task 2 (`listSourceFiles`).
4. **Invalid DOT from Claude.** `show_graph` returns `isError` with dot's
   first stderr line so Claude can fix it, and the pane keeps the previous
   graph. Pinned in Task 7.
5. **Two sessions at once.** Two Claude sessions never overwrite each
   other's PNG, because each session has its own file name. Pinned in
   Task 4 (`pngPath`).

  verified against ast-grep 0.51 on `ble-pair.sh` and a Vite config.
  ```yaml
  # bash
  id: fn
  language: bash
  rule: { kind: function_definition }
  ---
  id: cmd
  language: bash
  rule: { kind: command_name }
  ---
  id: exit
  language: bash
  rule: { kind: command, has: { kind: command_name, regex: "^exit$" } }
  ---
  id: source
  language: bash
  rule: { kind: command, has: { kind: command_name, regex: "^(source|\\.)$" } }
  ```

  ```yaml
  # typescript / tsx / javascript (language field substituted)
  id: fn
  language: typescript
  rule: { any: [ { kind: function_declaration }, { kind: variable_declarator, has: { field: value, kind: arrow_function } } ] }
  ---
  id: call
  language: typescript
  rule: { kind: call_expression }
  ---
  id: import
  language: typescript
  rule: { kind: import_statement }
  ```
- [ ] **Step 4: Implement `skeleton.ts`.**
  - A call or exit belongs to the innermost `Fn` whose line range contains
    it; otherwise to `(top)`.
  - Bash function names are the text before `(` or after `function `.
  - Bash `cmd` rows whose text is a defined fn become `kind:'fn'`.
  - Other bash `cmd` rows become `external` unless they are in `BASH_BUILTINS`:
    ```ts
    const BASH_BUILTINS = ['echo','printf','local','read','set','shift','return','exit','continue','break','test','[','[[','declare','export','unset','trap','eval','exec','source','.','command','mapfile','cd','true','false','wait','let','readonly','typeset']
    ```
  - Names not matching `^[A-Za-z0-9_.+-]+$` are dropped.
  - TS call names are the callee text up to `(`. Keep only calls to defined
    fns or imported bindings.
  - A dep spec is the quoted string in the row text. `resolve` (passed in)
    returns an absolute path only for relative specs that exist and contain
    no `node_modules` segment.
- [ ] **Step 5: Implement `extract.ts`.**

    - keep files where `langOf` is non-null, sorted;
    - cap at 200.
